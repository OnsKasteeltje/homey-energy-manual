# Publisher v1.0.14 — current-day series publication prep

Status: **PREPARED IN GITHUB / NOT DEPLOYED TO HOMEY**

Baseline: `src/homey/publisher/publisher-v1.0.13-control-evidence.js`.

## Goal

Publish the already-collected current-day 5-minute `dayHistory` outside Homey so realized-vs-plan analysis can be performed without new device polling or broad Homey Logic scans.

Target file:

`docs/data/energy-day-v2.json`

Expected source contract:

- `schema_version: 2.6`
- `source: EM2_DAY_SERIES_LOCAL_V0.6.1`
- `sample_interval_minutes: 5`
- samples include `p1W`, `p1L1W`, `p1L2W`, `p1L3W`, `solarEdgeW`, `goodWe4200W`, `goodWe2000W`, `teslaW`, `boilerW`, `boilerOn`, washer/dryer flags.

## Low-load design

Do **not** add any device reads, collection scans, or extra Homey trigger cadence.

Reuse the existing 15-minute Publisher gate. Only after the v1.0.13 publication gate has decided that a publication is due, add one targeted read of the canonical Planner Input variable:

```js
const PLANNER_INPUT_ID='39c7c169-34d7-4e14-a27b-520aca255032';
const plannerInputV=await Homey.logic.getVariable({id:PLANNER_INPUT_ID});
const plannerInput=parse(plannerInputV?.value);
const dayHistory=plannerInput?.dayHistory??null;
```

This reuses the current collector output already injected into `EM2_Planner_Input`; it does not create a new polling path.

Validation before publication:

```js
if(
  dayHistory &&
  String(dayHistory.schema_version||'')==='2.6' &&
  dayHistory.source==='EM2_DAY_SERIES_LOCAL_V0.6.1' &&
  Array.isArray(dayHistory.samples)
){
  // publish exact collector payload + publication metadata only
}
```

Do not derive, smooth, zero-fill, or rewrite measurement values inside Publisher. `null` remains unknown, never zero.

## Publication payload

Publish a shallow metadata wrapper only when necessary, preserving the collector payload:

```json
{
  "schema": "EM2_DAY_SERIES_PUBLISH_V0.1",
  "publishedAt": "<ISO>",
  "observabilityOnly": true,
  "controlImpact": "NONE",
  "sourceRevision": 3750,
  "day": { "...": "exact dayHistory payload" }
}
```

For website backwards compatibility, a deployment implementation may instead continue to write the raw `dayHistory` shape to `docs/data/energy-day-v2.json`; if so add only `published_at` and `publisher_version` fields and do not rename existing fields.

## GitHub write policy

Use the same GitHub token already read by Publisher v1.0.13. The current state publication remains unchanged. A second GitHub contents PUT may update `docs/data/energy-day-v2.json` after the state publication succeeds.

Recommended idempotency key:

```text
<date_local>|<last sample ts>|<last sample revision>|<sample count>
```

If unchanged from the last successful day-series publication, skip the second GitHub write.

## Homey API delta

Compared with Publisher v1.0.13, only on a due publication:

- +1 targeted `Homey.logic.getVariable()` for `EM2_Planner_Input`;
- +0 device reads;
- +0 `getVariables()` scans;
- +0 physical writes;
- +0 extra Homey triggers.

The additional GitHub GET/PUT is external network I/O, not Homey Logic fan-out.

## Why this is required

At 2026-08-31 21:00 local, `docs/data/energy-day-v2.json` was still dated 2026-08-29 and `energy-day-series-7d.json` was still generated on 2026-08-27, while the live Planner reported 53 current-day history samples from `EM2_DAY_SERIES_LOCAL_V0.6.1`. The current-day measurements therefore exist in the Planner input but are not being published to GitHub.

## Planner decision history companion

A rolling Planner snapshot file alone is insufficient for realized-vs-plan after the slot has passed. Preserve one compact record per planner run in a daily planner-slot history publication. The record should contain only:

- planner `generatedAt` / `sourceRevision`;
- current slot start/end;
- `warmWater` action;
- later v0.5 `WW_target_W` when available;
- `pvForecastW`, `baseLoadForecastW`, `pvSurplusBeforeFlexW`;
- `price_eur_kwh`, price quality;
- reason/allocation metadata.

This can be generated by the existing Planner Shadow publisher from the snapshot it already reads, so **no additional Homey read is required** there.

## Deployment gate

Do not deploy until:

1. payload validation is tested against a captured `EM2_Planner_Input` fixture;
2. current-day file is proven to update without device polling;
3. Publisher cadence remains 15 minutes;
4. no physical-write path exists;
5. existing `energy-state-v2.json` publication remains unchanged;
6. GitHub write conflict handling remains fail-safe and idempotent.
