# Power Intent P1 v0.2.3 TARGETED-READ LOW-LOAD candidate

Status: **READY FOR CONTROLLED DEPLOYMENT**

Baseline: active Homey Advanced Flow `EM v2 | 20 Power Intent | P1 v0.2.2 (Public decoupled)` (`19d9d8a6-ec32-4639-be5e-71e9f034d31b`), inspected directly on 2026-08-29.

## Runtime finding

The active v0.2.2 flow is already stage-2 decoupled from `EM2_Public_State`.

- Trigger: `EM2_Control_WW` variable changed.
- `EM2_Public_State` is publication-only and not a control dependency.
- The script is fail-closed and PURE SHADOW.
- It performs `Homey.logic.getVariables()` on every trigger.
- It exits early before writing `EM2_Power_Intent` when the previous valid Power Intent already has the same `sourceRevision`.

This means a time-only `EM2_Control_WW` update does **not** fan out into EV Gate/Adapter/Actuator writes when `sourceRevision` is unchanged, but it still causes one broad Logic collection enumeration.

## Why `EM2_Decision` must NOT become the sole trigger

Core revision changes only when the quantized state signature changes. `EM2_Control_WW` also contains WW scheduling/time-accounting semantics. Keep `EM2_Control_WW` as the downstream synchronization trigger.

## v0.2.3 low-load change

Replace the broad collection scan:

```js
const vars = await Homey.logic.getVariables();
```

with targeted reads:

```js
const [stateVar,decisionVar,wwVar,prevVar]=await Promise.all([
  Homey.logic.getVariable({id:IDS.EM2_State}),
  Homey.logic.getVariable({id:IDS.EM2_Decision}),
  Homey.logic.getVariable({id:IDS.EM2_Control_WW}),
  Homey.logic.getVariable({id:IDS.EM2_Power_Intent})
]);
```

Do not add a discovery `getVariables()` fallback in steady state. Missing/invalid bindings must fail closed.

## Expected load effect

Current v0.2.2 on every `EM2_Control_WW` change:

- 1 full Logic collection enumeration;
- 0 output write when `sourceRevision` is unchanged and previous intent is already valid;
- downstream cascade only when `EM2_Power_Intent` actually changes.

v0.2.3 target:

- 0 full Logic collection enumerations;
- 4 targeted Logic variable reads per trigger;
- same early-return/idempotency contract;
- unchanged downstream behavior.

## Safety invariants

- Keep schema `EM2_POWER_INTENT_V0.2`.
- Keep exact revision-alignment checks for State, Decision and WW Control.
- Keep fail-closed EV target 0 W on mismatch/invalid input.
- Keep `readOnly=true`, `controlMode='SHADOW'`, `deviceWrites=false`.
- No device reads, device writes, network calls or polling.
- Do not enable Watchdog or any disabled publisher/history flows for this deployment.
